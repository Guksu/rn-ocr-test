# 합성 배치 1차 결과 (Android)

| 항목 | 값 |
|------|-----|
| 측정일 | 2026-08-29 |
| 플랫폼 | Android 실기기 |
| 엔진 | ML Kit (`react-native-vision-camera-mlkit` 2.0.1, `language: KOREAN`) |
| 샘플 | 합성 12장 · 정답 성분 30개 |

## 결과

**근사일치는 12장 전부 30/30 (100%).** 아예 못 읽은 성분은 하나도 없었다.

### 크기 스윕 — 임계점이 나타나지 않음

| 한글 높이 | 완전일치 | 처리시간 |
|---|---|---|
| 11px | 29/30 (97%) | 374ms* |
| 15px | 29/30 (97%) | 226ms |
| 19px | 27/30 (90%) | 229ms |
| 23px | 29/30 (97%) | 234ms |
| 29px | **30/30 (100%)** | 227ms |
| 38px | 29/30 (97%) | 228ms |

\* 첫 실행이라 모델 로딩 시간이 포함된 것으로 보인다.

크기와 정확도 사이에 단조 관계가 없다. 11px에서도 97%가 나왔고, 19px이 오히려 가장 낮다.
**ML Kit 문서의 "문자당 최소 16px"이 이 조건에서는 제약으로 작동하지 않았다.**

### 조건 스윕 (29px 고정)

| 조건 | 완전일치 |
|---|---|
| 기울임 5° | 30/30 (100%) |
| 블러 1.6px | 29/30 (97%) |
| 저대비 0.35 | 28/30 (93%) |
| 복합(저대비+기울임+블러) | 28/30 (93%) |
| **노이즈** | **26/30 (87%)** |

노이즈가 가장 치명적이었으나, 그래도 87%다. 설정한 조건이 전반적으로 너무 약했다.

### 4MP 상한 대응 — 검증 완료

`oversize-12mp` (4032×3024): `keptFullResolution: false`, 에러 없음, 완전일치 28/30.
**축소가 실제로 일어났고 ML Kit이 거부하지 않았다.** 안드로이드 전용 throw 함정을 회피했음이 확인됐다.

## 오류 패턴 (가장 값진 관찰)

### 1. 한글 받침·모음 오인식 — 완전일치 실패의 전부

| 원본 | 인식 결과 |
|---|---|
| 다이포타**슘** | 다이포타**숨** / 다이포타**습** |
| 글라이**콜** | 글라이**골** |
| 글리세**린** | 글리세**립** / 글리세**란** |
| 셀**룰**로오스 | 셀**률**로오스 / 셀**를**로오스 |
| 토코페**릴** | 토코페**랍** |

전부 **편집거리 1**이다. 성분명 사전이나 LLM 후처리로 복구 가능한 종류다.

### 2. 하이픈 뒤 공백 삽입 — 구조적이고 재현성 있음

`폴리글리세릴-10라우레이트` → `폴리글리세릴- 10라우레이트`

**12장 중 거의 전부에서 나타났다.** 크기·조건과 무관한 구조적 오류다.
성분표에는 `1,2-헥산다이올`, `PEG-100`, `EDTA-2Na` 같은 표기가 흔해서 실전에서 계속 나온다.
저대비 샘플에서는 `폴리글리세릴- 1 0라우레이트` 로 숫자까지 쪼개졌다.

### 3. 그 밖

- 쉼표 ↔ 마침표 혼동: `소듐시트레이트.`
- 어절 중간 공백 삽입: `소듐하이알루로 네이트`, `나이아신 아마이드`
- 11px 샘플에서 헤더 `전성분:` 이 `선성문:` 으로 깨지고 별도 줄로 분리 (라인 15개, 나머지는 14개)
- 12MP 샘플에서 `알지닌` → `알지 ` (받침 유실)

## 해석

### 이 숫자를 실전 성능으로 읽으면 안 된다

합성 이미지는 완벽한 안티앨리어싱, 균일한 배경, 무손실에 가까운 렌더링이다.
실제 카메라 사진에는 센서 노이즈 · 렌즈 블러 · JPEG 압축 · 조명 불균일 · 곡면 왜곡이
**동시에** 얹힌다. **임계점이 안 나온 것은 "한글 OCR이 강하다"는 증거가 아니라
"우리가 만든 조건이 너무 쉬웠다"는 증거로 읽어야 한다.**

### 확실하게 확인된 것

1. **파이프라인 전체가 동작한다** — 이미지 준비 → OCR → 채점까지 끝단 검증 완료
2. **4MP 대응이 실제로 작동한다** (안드로이드 throw 회피)
3. **처리 시간 213~275ms** — 실시간 UX에 충분
4. **실패는 전부 편집거리 1의 받침·모음 혼동** — 후처리로 복구 가능한 성질

### 지금 바로 정할 수 있는 후처리 규칙

정답을 몰라도 적용 가능한 정규화:
- 하이픈 앞뒤 공백 제거 (`폴리글리세릴- 10` → `폴리글리세릴-10`)
- 숫자 사이 공백 제거 (`1 0` → `10`)
- 어절 끝 마침표를 쉼표로 취급
- 성분 구분 시 공백을 신뢰하지 말 것 (쉼표와 줄바꿈만 신뢰)
