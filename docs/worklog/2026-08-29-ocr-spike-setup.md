## 1. 개요

신규 사내 프로젝트에서 RN 기반 웹뷰를 담당하게 되어, 푸시 알림 · OCR · 소셜 로그인 · 로그인
영속화 네 기능의 기술 검증용 레포를 만들었다. 사용자는 RN 경험이 없으므로 각 결정의 근거를
설명하며 진행했다.

네 기능 중 **성분표 OCR 이 불확실성이 가장 크고 다른 결정(브릿지 규약 · 업로드 API · 촬영 UI)을
좌우**하므로 최우선으로 검증했다. 초기에 "이미지를 서버로 보내 처리"를 권고했으나, 사용자가
근거 없는 배제를 지적해 **온디바이스 OCR 을 실제로 측정한 뒤 판단**하는 방향으로 바로잡았다.
이 판단이 옳았음이 측정으로 확인됐다 — 공개 벤치마크가 존재하지 않아 직접 재는 것 외에
답을 알 방법이 없었다.

## 2. 작업내용

### 2-1. 설계 문답 (5라운드)

`grilling` 방식(설계 트리 + 프런티어)으로 진행했다. 매 라운드 전제가 확정된 질문만 묻고,
열린 질문에 의존하는 것은 다음 라운드로 미뤘다. 사실 조사는 서브 에이전트에 위임하고
결정만 사용자에게 물었다.

- 결과물: `docs/design/2026-08-29-webview-architecture.md` (승인됨)
- **번복 2건을 기록으로 남겼다** — ① OCR 을 서버 처리로 권고했다가 실증 우선으로 전환
  ② "심사 통과 가능 상태"의 의미를 스토어 준비물로 해석했다가 "기능 동작"으로 정정
- **범위 확정: 프론트엔드만.** 서버 LLM 비용·모델 선택 등은 논의에서 제외했다

### 2-3. 웹↔네이티브 브릿지

- `src/bridge/protocol.ts` — 규약 정본 (웹 레포와 동일 유지 필요)
- `src/bridge/injectedClient.ts` — 앱이 웹에 주입하는 `window.AppBridge`
- `src/bridge/useWebViewBridge.ts` — 메시지 라우팅. **출처 검증**으로 외부 페이지의
  네이티브 호출 차단, JSON 을 문자열로 한 번 더 감싸 주입 이스케이프 처리
- `src/bridge/handlers.ts` — action → 네이티브 동작
- `docs/bridge.md` — 웹 개발자용 인계 문서
- 안드로이드의 `injectedJavaScriptBeforeContentLoaded` 가 공식 문서상 100% 보장되지 않아
  **로드 전·후 이중 주입 + `appbridgeready` 이벤트**로 대응

### 2-4. OCR 라이브러리 선정

서브 에이전트로 후보 15종을 소스 레벨까지 조사했다. 비교표는 `README.md` 에 있다.

- 채택: **`react-native-vision-camera-mlkit` 2.0.1**
- 결정적 이유: Expo SDK 57 은 New Architecture 를 끌 수 없어 레거시 브리지 라이브러리가
  전부 리스크 등급이 된다. 그 조건에서 **정적 이미지에 한국어를 지정할 수 있는 유일한 후보**
- 가장 널리 쓰이는 `@react-native-ml-kit/text-recognition`(★583) 은 레거시 브리지 +
  iOS HEIC bbox 90° 회전 버그 미해결로 탈락
- Expo 모듈 계열 다수는 **한국어 모델 자체가 없다** (gradle·podspec 직접 확인)

### 2-5. 검증 앱 (1회용, `ocr-lab` 으로 격리)

- `src/ocr-lab/prepareImage.ts` — **크롭을 축소보다 먼저** 수행해 4MP 상한에서 픽셀 밀도 유지

- `src/app/ocr-lab/observe.tsx` — 관찰 모드 (이미지와 결과를 나란히)

### 2-6. 합성 샘플 생성기

실사 이미지 자동 수집을 세 경로로 시도했으나 모두 실패했다 — Open Food Facts 는 한국 제품
성분표 사진 0건 + 503 rate limit, Wikimedia Commons 는 사실상 없음, 이미지 검색 API 는
키 필요. **실사로는 분리할 수 없는 변수를 통제 측정**하는 쪽으로 전환했다.

- `tools/generate-ocr-samples.py` — 시드 고정, 재현 가능

### 2-8. 측정 결과

`docs/results/` 에 1·2차 분석이 있다. 핵심만:

| | 1차 (깨끗한 이미지) | 2차 (현실적 열화) |
|---|---|---|
| 크기 임계점 | **나타나지 않음** (11px 에서도 97%) | **10px 이하 0% / 15px 이상 100%** |
| 해석 | 조건이 너무 쉬웠음 | 실전에 가까운 신호 |

**2차의 발견**

1. **한글 안전선 15px.** 12px 미만은 쓸 수 없다. 점진적 저하가 아니라 절벽이다
2. **블러가 압도적 1위 리스크** — 3px 만 되어도 한 글자도 못 읽는다.
   반면 저대비 · 곡면 · 반사 · JPEG 압축 · 그림자는 근사일치 100% 를 유지했다
3. **조건이 겹치면 개별 내성이 무너진다** — 12px + 곡면 + 블러 조합이 근사 7%.
   각각은 83% / 100% / 무해였다
4. **실패를 감지할 수 있다** — 결과가 "0줄" 아니면 "83% 이상"으로 갈리고,
   실패 시 처리시간이 짧다(136~250ms vs 성공 311~377ms). 재촬영 유도가 가능하다
5. **4MP 대응 정상 동작** — 12MP 샘플이 축소 후 완전일치 100%

### 2-9. 도중에 해결한 문제

- **홈 디렉토리가 git 저장소였다.** `dev/ocr-test` 에 `.git` 이 없어 저장소 루트가 `~` 였고,
  이를 확인하지 않고 실행한 `git remote set-url` 이 홈 저장소 설정을 덮어썼다.
  원래 URL 로 원복 후 프로젝트에 `git init` 하고, `~/.git` 내용이 전부 GitHub 에
  존재함을 확인(커밋 해시 대조)한 뒤 제거했다
- **`<Link asChild>` 에 배열 스타일을 넘겨 런타임 렌더 에러** — expo-router 가 Slot 으로
  자식을 복제할 때 배열을 거부한다. `StyleSheet.flatten` 으로 미리 합쳐 해결.
  타입체크로는 안 잡히고 실행해야만 드러나는 종류다

## 3. 주의사항

### 실행 환경 제약

- **ML Kit 은 Apple Silicon iOS 시뮬레이터에서 빌드되지 않는다.** 프레임워크가
  `x86_64 arm64` fat binary 이고 xcframework 가 아니라 arm64 시뮬레이터 슬라이스가 없다.
  **iOS · Android 모두 실기기에서 실행해야 한다**
- **Android 는 4MP 초과 이미지를 다운샘플하지 않고 throw 한다.** iOS 는 알아서 줄이므로
  iOS 에서만 테스트하면 이 문제를 못 잡는다. `prepareImageForOcr` 를 반드시 거칠 것
- 개발 빌드 설치 후 JS 는 Metro 개발 서버에서 받아온다 (`npx expo start --dev-client`)

### 코드상 주의

- `src/bridge/protocol.ts` 는 웹 레포와 항상 같은 내용을 유지해야 한다. 한쪽만 바뀌면
  타입체크는 통과하고 런타임에서 조용히 깨진다
- `<Link asChild>` 의 자식에 배열 스타일을 넘기지 말 것
- `src/ocr-lab/`, `src/app/ocr-lab/`, `tools/` 는 **1회용 검증 코드**다. 제품 코드와 섞지 말고
  검증 종료 후 폐기한다
- git 저장소 상태를 바꾸는 명령 전에는 `git rev-parse --show-toplevel` 로 대상을 확인할 것

### 데이터 취급

- **테스트용 성분표 이미지를 git 에 커밋하지 않는다.** 타사 제품 패키지 · 타인 촬영물이다
- 합성 샘플(`assets/ocr-samples/*.jpg`)도 커밋하지 않는다. 생성기가 시드 고정이라
  `python3 tools/generate-ocr-samples.py` 로 언제든 동일하게 재생성된다
- **레포는 비공개 유지.** 소셜 로그인 키와 미출시 서비스의 기능 구성이 노출된다

### 측정 결과 해석 시

- **합성 결과를 실전 성능으로 읽으면 안 된다.** 1차에서 11px 97% 였던 것이 2차에서
  10px 0% 가 된 것이 그 증거다. 합성은 "한계선"을, 실사는 "실전 성능"을 답한다
- 완전일치는 **공백·쉼표·마침표를 무시한** 글자 일치다. 실패는 전부 한글 받침·모음
  오인식(편집거리 1)이었다

### 미해결

- **OCR 채택 합격선 미정** — 서버가 범위 밖이므로 이 레포는 수치만 산출하고 판정은 팀이 한다
- **iOS 미측정** — 같은 배치를 iOS 에서 돌려 플랫폼 간 차이를 확인해야 한다
- **실사 미측정** — 관찰 모드로 한글 인식은 확인했으나 정량 측정은 아직이다
- 촬영 가이드 UI 미착수. 측정이 정한 우선순위는 ① 흔들림·초점 ② 거리(15px 이상)
  ③ 조명·반사·곡면 순이다
- 로그인 · 푸시 · 영속화 미착수
- 하이픈 뒤 공백 삽입(`폴리글리세릴- 10라우레이트`)은 조건과 무관하게 재현된다.
  후처리 정규화 규칙이 필요하다
